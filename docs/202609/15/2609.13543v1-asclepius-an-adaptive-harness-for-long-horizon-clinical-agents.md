## 摘要
大语言模型智能体的评测大多基于短时、单任务的轨迹，而真实部署却要在资源竞争下持续运行数小时，从而暴露出另一类失败。我们以临床环境模拟器（CES）作为测试平台：在其中，智能体需在持续的时间与资源压力下管理整个急诊科班次；在结构化、多维度的评分下，长时程执行失败可在单次 rollout 中被可测量地显现。在 CES 上，现有智能体在大多数情况下能给出正确诊断，却无法完整、及时地执行关键处置，揭示出执行鸿沟。我们将这一鸿沟归因于三种长时程失败模式，并各自将其操作化为逐轨迹计数器：指令遵循漂移、治疗不完整，以及及时性上的严重程度公平性差距。随后我们提出 Asclepius，一种自适应智能体脚手架，包含：可自我演化的执行框架，能在班次之间依据轨迹级反馈重写操作手册；用于高风险治疗方案知识的外部化临床技能库；以及三个相互隔离的子智能体，将逐回合决策按患者队列进行划分。在执行框架演化过程中从未见过的留出批次上，Asclepius 相较一个强基线智能体框架将关键处置正确率提升 22%（p = 0.024），同时保持诊断准确性，并在来自三个模型家族的五个 LLM 评判者上取得一致增益；在完整的十批次集合上，关键处置提升达 25%，及时性提升达 13%。这三种失败模式构成一个耦合瓶颈：只有当三个组件协同作用时，才会出现显著的改善。

## Abstract
LLM agents are predominantly benchmarked on short, single-task trajectories, yet real deployments run for hours under contention, surfacing a different class of failures. We use the Clinical Environment Simulator (CES), in which an agent manages an entire emergency-department shift under continuous time and resource pressure, as a testbed: long-horizon execution failures manifest measurably in a single rollout under structured, multi-dimensional grading. On CES, current agents reach the correct diagnosis in most cases yet fail to deliver complete and timely critical actions, revealing an execution gap. We attribute this gap to three long-horizon failure modes, each operationalized as a per-trace counter: instruction-adherence drift, treatment incompleteness, and a severity-equity gap in timeliness. We then introduce Asclepius, an adaptive agent scaffolding with a self-evolving harness that rewrites the operating manual between shifts from trace-level feedback, an externalized clinical skills library for high-stakes regimen knowledge, and three isolated subagents that partition per-turn decisions across the patient queue. On held-out batches never observed during harness evolution, Asclepius improves critical-action correctness by 22% (p = 0.024) over a strong baseline agent framework while preserving diagnostic accuracy, with consistent gains across five LLM judges from three model families; on the full ten-batch set, improvements reach 25% on critical actions and 13% on timeliness. The three failure modes form a coupled bottleneck: decisive reductions appear only when all three components act together.

# Asclepius：面向长时程临床智能体的自适应执行框架 — 论文总结

## 1. 核心问题与整体含义

- **研究动机**：当前 LLM 智能体的评测几乎都基于**短时、单任务轨迹**，成功与否只在简短轨迹末端打分；而真实部署需要在资源竞争下**连续运行数小时**、交错处理多任务，会暴露一类短程基准完全看不到的失败。
- **测试床**：论文使用**临床环境模拟器（Clinical Environment Simulator, CES）**——一个多患者、连续时间、资源受限的急诊科班次模拟器（默认 6 小时 / 72 回合 / 12 名患者 / 4 床 6 护士 1 医生），从诊断、关键处置、及时性、处置去向四个维度以 1–5 分评分。
- **核心现象——执行鸿沟（execution gap）**：在 CES 上，现有智能体（含原始前沿模型与工具化基线框架）**诊断准确率很高（4.39/5）**，但**关键处置分数不足 3.0/5（2.94）**、及时性仅 3.34/5。即"诊断对、执行不到位"。
- **整体含义**：长时程失败不是单点能力缺陷，而是**多患者负载下的执行能力问题**；论文主张临床 AI 评测应从"孤立病例的诊断准确率"转向"跨患者队列的持续、完整、公平执行"。

## 2. 方法论：Asclepius 自适应脚手架

### 2.1 总体架构：两个耦合循环

- **外层循环（班次之间）**：把操作手册视为**可学习的自然语言工件**，由 proposer agent 依据已完成班次的轨迹级反馈重写。
- **内层循环（班次之内）**：主智能体借助 MCP 工具接口 + 临床技能库 + 三个隔离子智能体执行。

### 2.2 外层：自进化执行框架（Self-Evolving Harness）

- 记第 $t$ 轮手册为 $M_t$，proposer $P$（无模拟器访问、无患者场景定义、无留出批次访问）接收文件系统 $F_t$，其中含所有候选 $\{M_0,\dots,M_t\}$ 的手册、聚合/逐批次分数、逐患者评判行、逐回合动作记录与 LLM 调用审计日志。
- $P$ 导航 $F_t$，以当前最高分手册为编辑基线，输出 $M_{t+1}$；在搜索批次上评估后追加记录，迭代 $N$ 次后选搜索批次总体分最高者为 $M^*$。
- **proposer 系统提示的硬约束**：
  - (i) 每次编辑必须基于**跨多个批次、≥3 名患者**重复出现的失败模式；
  - (ii) 禁止写入患者/批次特定的硬编码知识；
  - (iii) 必须是实质性行为编辑，而非表面改写。
- 实验中以 Claude Opus 4.6 作为 $P$，迭代 $N=10$，选出 $M_7$（记为 v7）。

### 2.3 内层之一：临床技能库

- **按需检索**的参考模块，在治疗选择时加载并追加到工作上下文：
  - *临床决策指南*：表现→管理对照表（病种特异性药物、剂量、给药途径、非药物干预）+ 七类治疗完整性框架；
  - *临床推理模块*：治疗优先原则、"无裸诊断"规则、处置前核查清单、常见失败模式目录；
  - *模拟机制模块*：回合结构、动作生命周期、资源约束。
- 设计取向区别于 Voyager 等"在线学习/生长技能库"：这里是**人工策划的小规模、按病症索引的高风险知识库**，专门针对"治疗选择不完整"这一失效模式。

### 2.4 内层之二：三个隔离子智能体

- 将三个反复出现的逐回合决策外化为独立 LLM 调用、隔离上下文：
  1. **分诊优先级**：选择下一个接诊患者；
  2. **诊断形成**：综合检查结果给出工作诊断与处置建议；
  3. **治疗完成**：识别已诊断患者缺失的检查、药物与操作并确保下单。
- 子智能体提示词**仅来自手工手册 $M_0$**，跨配置固定，不引入额外医学知识；增益来源是**聚焦上下文、结构化输出约束、子智能体间协调**。
- **advisory vs. acting 两种变体**：advisory 下子智能体无 MCP 工具权限、只返回文本建议由主智能体解析执行；acting 下子智能体在其职责范围内直接调用 MCP（分诊子智能体安排床位、诊断子智能体提交处置与会诊、治疗子智能体下缺失医嘱），主智能体充当协调者。默认使用 acting。

### 2.5 三种失效模式的操作化计数器

| 失效模式 | 计数器 | 定义 |
|---|---|---|
| 指令遵循漂移 | **Drift** | 裸处置率（≤1 条前置治疗医嘱即处置，违反治疗优先规则）在早期（0–2h）→晚期（4–6h）的上升幅度 |
| 治疗不完整 | **Incomplete** | 已正确诊断患者中**零病种特异性治疗**的比例 |
| 严重程度公平性差距 | **Neglect** | 非重症与重症患者的及时性均值差（重症 = 基线整体接诊评分 ≤2） |

- Drift 采用**被试内比较**：两配置看到相同患者、相同到达顺序，故早晚差异不能归因于任务难度变化。

## 6. 主要结论与发现

- **执行鸿沟是当前智能体的属性，而非某个框架的产物**：原始 Claude Code 已呈现诊断/处置高（4.22/4.53）而关键处置/及时性低（2.69/2.65）的不对称，基线框架延续该模式。
- **Asclepius 显著缩小鸿沟**（全 10 批次）：总体 +0.30（p<0.01）、关键处置 **+0.73（+25%，p<0.001）**、及时性 **+0.45（+13%，p<0.01）**；诊断（−0.02）与处置（+0.03）基本不变（p>0.8），说明增益来自执行而非临床判断。
- **留出批次**（n=48）：关键处置 **+0.625（+22%，p=0.024）** 仍显著，及时性（+0.312）与总体（+0.193）为正但不显著；作者将此视为主要量化主张。
- **多评判一致**：5 个评判全部复现，关键处置 Δ 在 +0.65~+0.76 之间（均 p<0.001），其中 4 个评判的及时性增益大于主评判。
- **组件不可替代、构成耦合瓶颈**：单组件中 harness 增益最大（总体 +0.18，关键处置 +0.38，及时性 +0.34，且是唯一在单维度上通过校正显著阈值的单组件），技能次之（+0.12），子智能体最小（+0.04）；但**三个计数器的决定性下降只在三者合用时出现**——Drift 从基线 +41pp 降至 +2pp（16%→57% 对 10%→12%）、零治疗率 19%→9%、及时性公平差距 1.13→0.23。
- **组件效应互相"溢出"**：技能库与子智能体对漂移的抑制甚至强于 harness（+18pp、+16pp vs. +32pp），harness 反而取得最低零治疗率（7%）——印证失败模式彼此耦合而非正交。
- **acting 优于 advisory**：总体 +0.10、关键处置 +0.26、及时性 +0.10，且诊断/处置无退化；原因是子智能体自行下单避免了主智能体对长结构化建议的改写与词汇解析失败。
- **harness 搜索轨迹非单调**：v0→v2 快速上升，v4–v5 平台，v6–v8 形成高性能平台（选 v7），v9–v10 在诊断或处置上回退；v0→v7 的编辑包括"处置前治疗枚举例程"与 13 条新增表现行、约 7 条管理条目

- v0→v7 的编辑包括"处置前治疗枚举例程"与 13 条新增表现行、约 7 条管理条目等实质性行为改写，而非措辞润色；v9–v10 的回退表明**搜索目标（总体分）本身不能完全约束多维度表现**，单纯延长迭代可能损害诊断或处置质量。
- **三个计数器共同刻画了"负载下的执行退化"**：基线在班次早期即已开始漂移（16%→57%），说明失效并非只发生在疲劳末期，而是**随资源竞争累积**；Asclepius 将漂移压缩到近零（10%→12%），并使重症与非重症的及时性差距几乎消失（1.13→0.23），指向公平性可作为长时程执行的显式优化目标。

## 7. 局限与开放问题

论文自身与从方法设计可推断的局限可归纳为以下几类：

- **执行方差未被量化**：每配置每批次仅一条轨迹，混合效应模型只吸收患者与批次的异质性，无法区分"系统改进"与"单次运行的运气"。对于本身就依赖采样的 LLM 智能体，run-to-run 方差可能与被测量的效应同量级，这是**最需要补做的实验**（多随机种子、报告运行间方差与置信区间）。
- **单一骨干与单一环境**：主智能体、proposer 均为 Claude Opus 4.6，Patient Engine 为 GPT-4.1；仅在 CES 一个急诊科模拟器上验证。跨模型家族、跨临床科室（如 ICU、门诊、多科室协同）以及非临床长时程领域（如运维、客服队列）的可迁移性未知。
- **harness 的独立边际贡献不显著**：消融中进化手册单独加入时，全批次总体 +0.12（p=0.36）、留出 +0.02（p=0.88），故"自进化手册是否真正必要"仍未被强证据支持；当前结论只能落在**系统层面**（三者耦合才有效），而非组件层面。
- **评测者仍为 LLM**：虽有 5 个跨家族评判复现同一模式，但 LLM 评判对"关键处置是否完整""是否违反治疗优先"这类临床规范的判定本身可能存在系统性偏差，缺少**临床专家标注**的一致性研究。
- **CES 的保真度边界**：模拟器以规则与 LLM 驱动的患者引擎实现，隐藏恶化阈值、检查延迟、资源队列均为参数化设定；真实急诊的并发、沟通、家属因素、伦理与法律约束远更复杂，执行鸿沟的绝对幅度不可直接外推到临床部署。
- **proposer 的反馈闭环风险**：proposer 依据聚合分数与逐患者评判行编辑手册，可能**过度拟合搜索批次的特定失败模式**，或在无模拟器访问的前提下写入看似合理但实际有害的规则；留出批次缓解但未消除该风险，且缺少对编辑内容的安全性审查机制。
- **计数器为代理指标**：Drift、Incomplete、Neglect 三者是对失效模式的操作化近似，与真实临床不良事件之间没有建立映射，其阈值（如 ≤1 条前置医嘱即算裸处置）具有人为设定成分。

## 8. 总体评价与启示

- **概念贡献大于单点性能提升**：论文最有价值的产出是**"执行鸿沟"这一诊断性概念**及其操作化——把"诊断对但执行不到位"从轶事观察变成可跨系统比较、可分解为漂移/不完整/不公平三类失效的量化对象。它提示长时程智能体的评测重心应从"末端正确率"转向"过程中的持续合规与资源公平"。
- **方法论范式：把操作手册当作可学习的自然语言工件**。外层自进化 + 内层技能库/子智能体的双层设计，为"不训练模型、仅通过自然语言工件与上下文工程提升长时程行为"提供了一条可复现路径；其关键在于**用轨迹级、跨患者重复出现的失败模式驱动编辑**，而非针对单例打补丁。
- **组件耦合的启示**：三个组件的增益不可简单相加，且决定性改善只在合用时出现——这暗示长时程执行失败是**系统性瓶颈**而非若干独立缺陷，未来工作应更关注组件间的交互设计，而非孤立堆叠模块。
- **对临床 AI 的实践含义**：即使诊断能力接近饱和，**处置完整性与及时性**仍是长时程部署的主要短板，且资源竞争会放大对非重症患者的忽视；因此临床智能体的安全评估应显式纳入公平性与"治疗优先"合规指标，而非只看诊断准确率。
- **开放方向**：多随机种子下的方差量化、跨模型/跨环境的泛化、harness 边际贡献的更强证据、专家一致性研究，以及将三计数器与真实不良事件建立经验映射，是推进该框架从"演示有效"走向"可部署可信"的关键步骤。
