## 摘要
可穿戴健康问题通常需要在结构化记录上结合数据检索、纵向分析和健康建议。将完整记录与复合查询一并提示单个大语言模型，会掩盖每个请求是否被执行以及哪些证据支持了答案。我们提出一种任务导向的多智能体框架，将复合查询表示为不同的意图以及具有显式意图内依赖关系的类型化任务。专用智能体分别执行检索、分析和建议任务；隔离的意图状态在聚合之前保留请求边界与证据关系。我们在一个包含 10,000 名虚拟用户、每人一个月纵向可穿戴记录的合成数据集上评估该框架，涵盖结构化数据检索、多意图识别和整体响应质量。在 1,500 个检索问题上，查询智能体达到 98.3% 的准确率，而直接 LLM 基线为 97.9%，同时将查询阶段的平均 token 消耗从 6,869 降至 3,136。在 180 个多意图问题上，管理智能体实现了 100.0% 的多意图覆盖率和 94.4% 的多重集 Jaccard 相似度。在当前合成评估设置下，我们的方法在两类问题上均获得更高的平均可信度（Trustworthiness）与透明度（Transparency）得分，而可操作性（Actionability）并未持续提升。这些结果为以下观点提供了初步证据：显式任务组织能够支持与任务相关的数据访问以及基于数据的纵向分析，同时将健康建议生成和在真实可穿戴数据上的验证留作待解决的挑战。

## Abstract
Wearable health questions often combine data retrieval, longitudinal analysis, and health advice over structured records. Prompting a single large language model with a complete record and a composite query obscures whether every request is executed and which evidence supports the answer. We propose a task-oriented multi-agent framework that represents a composite query as distinct intents and typed tasks with explicit intra-intent dependencies. Specialized agents execute retrieval, analysis, and advice tasks; isolated intent states preserve request boundaries and evidence relationships before aggregation. We evaluate the framework on a synthetic dataset of $10{,}000$ virtual users with one month of longitudinal wearable records, covering structured data retrieval, multi-intent recognition, and overall response quality. Across $1{,}500$ retrieval questions, the Query Agent achieves $98.3\%$ accuracy, compared with $97.9\%$ for the Direct LLM baseline, while reducing average query-stage token consumption from $6{,}869$ to $3{,}136$. On $180$ multi-intent questions, the Manager Agent achieves $100.0\%$ Multi-Intent Coverage and $94.4\%$ Multiset Jaccard Similarity. Under the current synthetic evaluation setting, our method receives higher mean Trustworthiness and Transparency scores on both question categories, whereas Actionability does not improve consistently. These results provide preliminary evidence that explicit task organization can support task-relevant data access and data-grounded longitudinal analysis, while leaving health advice generation and validation on real wearable data as open challenges.

- **研究背景**：可穿戴设备持续产生涵盖运动、日常活动、睡眠与生理事件的纵向记录。这类记录规模大、结构复杂，用户无法直接检查，因此需要自然语言接口来检索测量值、跨时间比较指标并获取健康支持信息。
- **核心问题**：论文聚焦于**复合可穿戴健康查询**——即在一个问题中混合多个请求（如"检索某日步数 + 分析房颤与运动/睡眠的关系 + 给出改善建议"），并要求每个请求都能追溯到其使用的证据。
- **三大技术挑战**：
  - 一个问题可能包含多个不同用户请求，包括**同一意图类型的重复出现**以及必须保留的共享时间约束；
  - 分析或建议请求可能依赖**多个检索操作产生的证据**，执行顺序本身无法指定每个下游步骤应获取哪些前驱结果；
  - 自然语言时间表达和健康指标必须映射到记录中的**精确日期和字段**。
- **现有方法的不足**：将完整记录与复合查询直接提示给单个 LLM，会把请求覆盖、结构化数据访问和证据流都隐含在同一生成过程中，导致无法确认每个请求是否被执行、哪些证据支持了答案。作者强调，这一缺口本质上是**执行表示（execution representation）问题**，而非智能体数量问题。
- **整体含义**：论文提出以"意图—任务"层级结构显式表示复合查询，把请求边界、任务依赖和证据关系显式化，并区分确定性结构化访问与语言模型生成，从而提升任务相关数据访问的可追溯性与纵向分析的可解释性。

## 2. 论文提出的方法论

### 核心思想
- 将复合查询表示为**有序意图序列**，每个意图分解为**带显式前驱依赖的类型化任务**；任务类型确定性地路由到专用智能体执行，意图状态相互隔离，最终按原问题顺序聚合各意图的终端结果。

### 关键形式化
- **用户记录**：$D_u$ 为用户 $u$ 的完整结构化记录，$B_u = \text{ExtractProfile}(D_u)$ 为提取出的画像（人口统计、生活方式、病史）。
- **意图识别**：$I = \text{RecognizeIntents}(q) = (i_1, \dots, i_N)$，每个意图 $i_j = (\text{text}_j, \kappa_j)$，类型空间 $\mathcal{C} = \{\text{query}, \text{analyse}, \text{advice}\}$；共享约束被复制到每个受影响的意图描述中，重复类型保持为独立序列元素。
- **任务分解**：每个意图分解为有序任务序列 $T^{(j)} = (t^{(j)}_1, \dots, t^{(j)}_{M_j})$，其中 $t^{(j)}_m = (\text{id}^{(j)}_m, \text{desc}^{(j)}_m, c^{(j)}_m, D^{(j)}_m)$，$D^{(j)}_m$ 为前驱 ID 集合。
- **依赖约束**：$D^{(j)}_m \subseteq \{\text{id}^{(j)}_p \mid 1 \le p < m\}$，即只能引用**同一意图内已完成的前驱任务**；Query 任务无前驱（$c^{(j)}_m = \text{query} \Rightarrow D^{(j)}_m = \emptyset$）。
- **前驱结果收集**：$P^{(j)}_m$ 为由 $D^{(j)}_m$ 指定的有序三元组（来源 ID、任务描述、结果），保留证据来源。
- **任务执行契约**（式 7）：Query 任务调用 `QueryAgent(t, B_u, D_u)`；Analyse/Advice 任务调用对应智能体，仅接收 $B_u$ 与显式前驱结果 $P^{(j)}_m$，不直接访问 $D_u$。
- **最终响应**：$y = \Gamma(q, R_I)$，其中 $R_I$ 为按意图顺序排列的终端结果序列，渲染器不重新访问原始记录，且被指示只使用提供的终端结果。

### 智能体设计
- **Manager Agent**：识别有序意图、构造类型化任务与同意图依赖、按类型路由、维护意图局部结果、按原问题顺序聚合。
- **Query Agent**（四阶段流水线，式 9）：
  - `DateResolve`（LLM）：解析参考日期与目标日期序列 $d^{(j)}_m$；
  - `QueryEngine`（确定性结构化访问）：按日期索引检索有序记录 $X^{(j)}_m$；
  - `Textualize`（确定性）：保留日期、字段语义与原始值生成证据文本 $S^{(j)}_m$；
  - `QueryAnswer`（LLM）：基于任务、画像和证据生成答案，结果 $r^{(j)}_m = (S^{(j)}_m, y^{(j)}_{Q,m})$ 同时保存证据与答案。
- **Analyse Agent**：接收任务、画像与前驱结果，支持单指标时间对比与多指标联合组织两种模式，输出有序的证据支撑发现序列；不重新访问 $D_u$，不引入外部数值，不将共现解释为因果。
- **Advice Agent**：基于画像与依赖证据生成个性化建议，明确"证据解释 → 个性化推荐 → 行动与监测指导"流程；提供一般性健康支持而非临床诊断，不更改处方治疗，证据不足时使用保守措辞并建议寻求专业评估。
- **结果聚合**：$c^{(j)}_{M_j} = \kappa_j$，Manager 仅选取每个意图的终端结果 $r^{(j)} = r^{(j)}_{M_j}$，保持意图顺序，不投票、不跨意图合并中间证据。
- **算法流程（Algorithm 1）**：提取画像 → 识别意图 → 对每个意图：分解任务 → `ValidateTaskGraph`（校验类型、ID 唯一性、前驱引用合法性、Query 空依赖、终端类型一致性）→ 初始化意图局部结果存储 → 按顺序执行任务（Query 直接执行，其余先 `CollectResults` 收集前驱）→ 存结果 → 终端结果入 $R_I$ → 最终渲染。

## 6. 论文的主要结论与发现

- **结构化检索**：Query Agent 准确率 98.3%，Direct LLM 97.9%，差距仅 0.4 个百分点且未做显著性检验；但平均 token 消耗从 6,869 降至 3,136（降低约 54.3%）。证据仅支持"准确率相当但检索上下文更少"，而非推理能力更强或端到端成本更低。
- **多意图识别**：Manager Agent 达到 100.0% MIC 与 94.4% Multiset Jaccard。两者差距表明**类型覆盖可靠，但重复意图数量的还原仍有错误**；两项指标均不评估意图边界、文本跨度或相对顺序。
- **整体响应质量**：
  - 多意图问题（60 题）：Trustworthiness 3.8 vs. 3.5，Transparency 3.9 vs. 3.1，Actionability 3.0 vs. 3.2；
  - 纵向趋势问题（100 题）：Trustworthiness 4.5 vs. 4.3，Transparency 4.1 vs. 3.9，Actionability 1.7 vs. 1.6。
  - **Trustworthiness 与 Transparency 在两类问题上均更高，Actionability 未持续提升**。
- **总体结论**：显式任务组织能够支持任务相关的数据访问与基于数据的纵向分析，但健康建议生成（尤其 Actionability）与在真实可穿戴数据上的验证仍是开放挑战；当前结果不构成因果关系。

## 7. 优点

- **问题形式化清晰**：用"意图—任务"层级统一表示请求边界、操作类型与前驱证据关系，形式化定义严谨（式 1–9），并区分了"意图类型描述结果"与"任务类型描述操作"。
- **意图隔离设计精巧**：依赖被限制在同一意图内，跨意图中间结果不进入下游上下文；Advice 意图需要证据时新建意图内 Query 任务而非复用其他意图结果，有效防止上下文污染。
