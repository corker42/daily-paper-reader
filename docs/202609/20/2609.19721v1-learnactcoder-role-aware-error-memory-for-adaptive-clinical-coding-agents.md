## 摘要
临床编码智能体会反复遇到相同的失效模式，包括不支持的编码、遗漏已记录的病症、特异性错误以及操作编码惯例不匹配。我们提出 Learn-Then-Act，一种推理时自适应框架，它将来自一小批带标签的 LEARN 批次的错误转化为结构化的错误知识库（MistakeKDB）。假阴性经验被路由至面向召回的 Coder，而假阳性经验被路由至面向精确率的 Judge。我们将该框架实例化为 LearnActCoder，一个在可用时以查找表作为依据的 Coder-Judge 临床编码流水线。在 150 份匹配的 MIMIC-III 病历记录上，结构化的 MistakeKDB 将 CPT F1 提高了 5.9 个百分点，而原始示例记忆和反思式记忆仍接近无记忆基线；ICD-9 的改善不显著。在一个匹配的 MIMIC-IV 队列上，记忆使 ICD-10 编码转向更高精确率，但以召回率为代价，F1 在统计上保持不变。将相同记忆应用于 1,000 份留出的 MIMIC-III 病历记录时，可维持稳定的 ICD 工作点，提供了规模/稳定性证据。总体而言，这些结果与以下观点一致：结构化的、由反馈导出的错误记忆有助于在不更新权重、也不改变底层工作流程的情况下，使临床编码行为跨病例自适应。CPT/HCPCS 的绝对性能仍然较低，且该系统是在回顾性而非临床部署环境中评估的。

## Abstract
Clinical coding agents repeatedly encounter the same failure modes, including unsupported codes, missed documented conditions, specificity errors, and procedure-coding convention mismatches. We introduce Learn-Then-Act, an inference-time adaptation framework that converts errors from a small labeled LEARN batch into a structured Mistake Knowledge Database (MistakeKDB). False-negative lessons are routed to a recall-oriented Coder, while false-positive lessons are routed to a precision-oriented Judge. We instantiate the framework in LearnActCoder, a Coder-Judge clinical coding pipeline with lookup-table grounding where available. On 150 matched MIMIC-III notes, structured MistakeKDB improves CPT F1 by 5.9 percentage points, while raw-example and reflection-style memories remain near the no-memory baseline; the ICD-9 improvement is not significant. On a matched MIMIC-IV cohort, memory shifts ICD-10 coding toward higher precision at a recall cost, leaving F1 statistically unchanged. Applying the same memory to 1,000 held-out MIMIC-III notes maintains a stable ICD operating point, providing scale/stability evidence. Overall, the results are consistent with structured, feedback-derived error memory being useful for adapting clinical coding behavior across cases without weight updates or changes to the underlying workflow. Absolute CPT/HCPCS performance remains low, and the system is evaluated retrospectively rather than in clinical deployment.

## 1. 核心问题与整体含义

- **背景**：医疗编码将临床文档映射到 ICD、CPT/HCPCS 等标准词表，直接影响报销、利用率统计、质量报告、审计风险与下游临床研究。该任务对语言模型极难：病历中大量"临床上合理"的概念未必可编码；编码特异性依赖细粒度文档；输出空间达数万标签。
- **核心痛点**：现有 LLM 编码系统（提示、检索、分阶段推理、多智能体工作流）能改进单次预测，但**无法复用已被纠正的错误**。实践中编码错误高度重复：反复过度编码证据薄弱的诊断、漏掉状态/病史编码、特异性层级选错、混淆专业版与机构版手术编码惯例。把每份病历当作独立的零样本回合，等于丢弃了审计反馈。
- **研究问题**：在不更新模型权重、不改变既有工作流的前提下，智能体如何跨病例复用被纠正的错误经验？
- **整体含义**：论文主张的并非"记忆必然提升准确率"，而是一个更窄但更实用的命题——**结构化、由反馈导出的错误记忆可作为"工作点（operating point）调控机制"**，系统地改变精确率/召回率的权衡行为。

## 2. 方法论：Learn-Then-Act

### 2.1 核心思想
将"预测 vs 参考标签"的失配转化为**可复用的自然语言教训**，并按**错误方向（假阴性/假阳性）**路由给角色互补的智能体。关键设计选择是**角色感知路由**：

$$M_{FN} \rightarrow \text{Coder（偏召回）},\qquad M_{FP} \rightarrow \text{Judger（偏精确）}$$

底层 Coder–Judge 工作流与模型权重保持固定，仅跨病例改变角色专属的提示记忆。

### 2.2 基础流水线：生成—落地—审查
- **Coder 智能体（召回导向）**：输入出院病历，输出结构化 JSON（候选编码、描述、置信度、支持证据）；提示偏向召回，先做初始抽取，再做一次类别级"我漏了什么？"的补漏遍历。因此它是假阴性教训的天然接收者。
- **CodeLookupDB 落地校验（非生成式）**：在 Judge 审查前，对候选编码标识符查表。基准配置含 **192,214 条 ICD-10-CM 条目**（UMLS 衍生来源）与 **26,533 条 CPT/HCPCS 条目**（含描述与层级类别）。报告候选"存在/未找到"并向 Judge 暴露参考描述。该步骤只解决"编码不存在或描述不匹配"，**不能证明存在编码在临床上成立**。因加载的是 ICD-10 词表，**ICD-9 直接查表被禁用**。
- **Judge 智能体（精确导向）**：接收病历、Coder 提案与查表报告；优先考虑查表状态、病历级证据、编码描述与临床语境的一致性、特异性、输出格式合规性；可接受提案或要求重出完整编码集。它是假阳性教训的主要接收者。
- **辩论协议**：Coder 生成 → 查表 → Judge 审查，最多迭代 **R = 3 轮**，形成"广搜 + 精滤"架构；有无 MistakeKDB 时使用同一架构。

### 2.3 两阶段流程
- **Phase 1 — LEARN**：基础流水线编码 $N_L$ 份 LEARN 病历后，**MistakeAnalyzer** 接收病历、预测与参考行政编码；对每个假阳性/假阴性记录解释与可迁移教训，并归入六类之一：**过度编码、编码不足、文档缺口、特异性错误、错误编码类型、其他**。结果构成 **MistakeKDB**——按错误类别、编码族、临床语境索引的结构化 JSON 仓库。
- **Phase 2 — ACT 与角色感知路由**：假阴性教训注入 Coder 提示以扩展类别搜索（例如"检查慢性/状态类编码"）；假阳性教训注入 Judge 提示以收紧证据要求（例如"仅由鉴别诊断或顺带提及支持的诊断应拒绝"）。
- **记忆表示**：每条记录存错误类别、涉及编码、自然语言解释、可迁移教训；相似教训被合并，高频模式在注入前获得更高优先级。属"紧凑错误记忆"，而非对历史病历全文的检索。

## 3. 实验设计

### 3.1 数据集与标签
- **MIMIC-III**：ICD-9 + CPT 实验；**MIMIC-IV**：ICD-10 + HCPCS 实验。
- 参考标签取自对应的诊断、操作与 CPT/HCPCS 事件表，论文明确称其为**"参考行政标签"而非临床金标准**（账单记录可能编码了单份出院小结未陈述的信息）。
- **MIMIC-III**：LEARN 批 25 份标注出院小结；ACT 评估在病历级留出，报告 250 与 1,000 两个规模；其中 **150 份子集额外做无记忆重编码**以形成配对比较。
- **MIMIC-IV**：25 份 LEARN 病历建记忆，全部 250 份 ACT 病历同时做"有/无记忆"编码。
- 两数据集另有 **500 份**无 MistakeKDB 的基础流水线基准。

### 3.2 模型与实现
- 全部实验使用 **GPT-5**；实现基于 **LangChain**，JSON 结构化输出、CodeLookupDB，Coder–Judge 最多 3 轮。所有配对比较固定病历集、模型族与流水线结构，仅改变 MistakeKDB 的有无。

### 3.3 指标
