Abstract 

LLM agents for clinical text-to-SQL applications reason autonomously over multi-ple steps but cannot assess whether their own reasoning or outputs can be trusted. In high leverage applications such as healthcare, this presents a critical risk where system mistakes can be costly. These reliability failures are also resource failures: an incorrect reasoning trajectory spends computation budget on outputs that must be discarded. We introduce Sentinel, a trajectory-derived, classifier-based confi-dence layer that analyzes an agent’s reasoning, code and database outputs to decide at three points whether to stop: refusing unanswerable questions before the agent runs, halting doomed trajectories mid-run, and withholding untrustworthy answers at delivery. Here, utilizing Chow’s rule, we optimize decisions under the EHRSQL shared task’s Reliability Score, which penalizes incorrect answers given a utility weighting, and find on the benchmark EHRSQL that Sentinel raises this score from 

+0 .08 to +0 .24 when mistakes have a low utility weighting, well above the +0 .03 

earned by refusing every question, with delivered-answer accuracy rising from 54% to 69% as coverage falls from 84% to 55%. At higher stakes the agents we test rarely answer reliably enough to deliver, and Sentinel detects this on its own, abstaining to that same +0 .03 where the unmonitored agent scores −3.02 . The same stopping decisions cut computation: at low stakes, where the system still answers, Sentinel eliminates 13–28% of agent steps at little or no reliability cost. 

1 Introduction 

Recent advances in LLMs have shifted tabular reasoning from its traditional Table QA framework [Pasupat and Liang, 2015, Zhong et al., 2017, Yu et al., 2018] to increasingly autonomous agents that can reason through their decision-making. Rather than producing a final answer in one pass, these agents can issue SQL queries or table operations, inspect the intermediate results, and revise their next steps based on that feedback [Yao et al., 2023, Wang et al., 2024, Kwok et al., 2026b]. With this autonomy comes a new risk: an agent given full freedom to reason must also discern for itself whether that reasoning and resulting response can be trusted. In clinical settings, the cost of a wrong answer is high, explicit, and often greater than the cost of declining [Swaminathan et al., 2024]. There are two failure modes we consider that carry distinct harms. The first is incorrectness , where the database has enough information to answer the question, but the agent returns an answer that differs from the correct result. For example, the agent may return a wrong lab value, medication count, or cohort size, but is delivered in the same fluent, confident register as a correct one. Clinicians are rarely positioned to audit the SQL that produced it, and tend to accept confident machine output even when it is wrong [Goddard et al., 2012]. The second failure mode is unanswerability , where the database lacks the information needed to answer the question. In this case, the correct behavior is to abstain rather than return an unsupported answer. Yet agents

These reliability failures are simultaneously resource failures. Each agent step is a full, costly LLM call [Chen et al., 2024] over a growing context, so a trajectory that should never have started wastes computation and a user’s time, producing an output the system must discard. Responses to unanswerable questions show some of the highest costs because the correct action, abstention, is available at step zero; everything afterward is waste by construction. In our experimentation, a vanilla GPT-4o agent on average spends 2.5 reasoning steps per unanswerable question before failing. When it fabricates an answer, it takes 3.35 steps on average, 58% more than the 2.12 steps it takes on average when it correctly refuses (per-agent step economics in Appendix K). Knowing when to stop , before the first step, mid-trajectory, or at delivery, is therefore one decision problem serving two goals at once: not delivering costly mistakes, and not paying for them. The obstacle is that the agent cannot reliably assess its own correctness. LLMs can be poorly calibrated when verbalizing confidence, and may express high confidence even when their answers are wrong [Xiong et al., 2024]. More fundamentally, the model’s stated reasoning may not reflect the actual reasons behind its final answer, making chain-of-thought an unreliable indicator of model behavior [Turpin et al., 2023, Lanham et al., 2023]. The interaction trajectory, however, includes externally grounded signals that the agent does not control, including executed SQL, error messages, empty result sets, and failed schema references. A separate monitor can learn how these externally observed patterns correlate with eventual success across past trajectories, allowing it to estimate reliability without depending on the agent’s own explanation or confidence estimate. Figure 1 demonstrates both failures modes and Sentinel, a trajectory-derived confidence layer 

wrapping an unmodified ReAct agent [Yao et al., 2023]. Two small text classifiers read the agent’s own transcript: an answerability head powers an exit gate that halts trajectories on unanswerable questions, while a correctness head provides a calibrated estimate that stops doomed trajectories mid-run and, via Chow’s rule [Chow, 1970], withholds untrustworthy answers at delivery. Rather than training the agent to be more correct, the system delivers less costly mistakes by refraining from answering, and stops paying for trajectories that will not end in a delivered correct answer. Our contributions can be summarized as follows: • Stakes-aware reliability. We formulate reliability for clinical text-to-SQL agents as a stakes-dependent decision problem, where the cost of an incorrect answer can exceed the cost of abstaining. 2• Trajectory-derived monitoring. Sentinel introduces a confidence layer that scores the agent’s evolving trajectory rather than relying solely on its final output or self-reported confidence (Figure 2). The monitor operates before execution, during reasoning, and at delivery, allowing it to refuse unanswerable questions, stop low-confidence trajectories, and withhold unreliable final answers across five agent models. • Resource-aware early stopping. We show that the same confidence estimates can reduce computation by stopping trajectories that are unlikely to produce a useful answer, reducing unnecessary reasoning steps and latency while preserving reliability at several operating points. 

2 Related work 

Text-to-SQL over EHRs and abstention. Early text-to-SQL systems focused on mapping natural-language questions to executable SQL, including Seq2SQL [Zhong et al., 2017] and the Spider benchmark for complex cross-domain querying [Yu et al., 2018]. Later work introduced multi-step reasoning, decomposition, and execution feedback to improve performance on complex queries [Pourreza and Rafiei, 2023, Wang et al., 2018]. In the clinical domain, EHRSQL [Lee et al., 2022] introduced unanswerable questions, making abstention a first-class capability for clinical text-to-SQL. TrustSQL [Lee et al., 2024a] introduced the penalty-based Reliability Score, later the official metric of the EHRSQL 2024 shared task [Lee et al., 2024b], and evaluated pipelines that split abstention into unanswerable-question detection and SQL-error detection, the same decomposition our two heads adopt. Shared-task systems such as ProbGate [Kim et al., 2024] filter unanswerable questions by thresholding token log-probabilities; our training-free telemetry baseline uses the same token-level signals. The nearest reliability baseline is the IDK filter of Broecker et al. [2026], a trainable uncertainty filter for function-calling agents whose IDK score coincides with RS(1) on answerable questions; Appendix K compares gains on that shared scale. Unlike these approaches, Sentinel derives confidence from the agent’s reasoning trajectory and applies that signal at multiple decision points to refuse unanswerable questions, stop low-confidence trajectories early, and withhold unreliable final answers. 

Selective prediction and agent confidence. Classification with a reject option dates to Chow [1957, 1970]. Modern selective-prediction methods allow a model to abstain on low-confidence inputs and study the resulting trade-off between coverage, the fraction of inputs on which the model makes a prediction, and selective risk, the error on those retained predictions [Geifman and El-Yaniv, 2017, Kamath et al., 2020, Hendrickx et al., 2024]. We apply this framing at two distinct checkpoints of an agentic trajectory rather than to a single prediction. First, we use confidence during execution to see whether an ongoing trajectory should be stopped early when unlikely to succeed. Second, we use confidence at delivery time to decide whether the completed answer should be returned or withheld. Uncertainty signals have been drawn from token probabilities and entropy, verbalized confidence, and learned confidence heads [Kadavath et al., 2022, Xiong et al., 2024]. Our trajectory features draw from three different approaches: token-level confidence estimation [Kadavath et al., 2022, Kim et al., 2024, Somov and Tutubalina, 2025], execution-guided text-to-SQL [Wang et al., 2018], and clause-level SQL verification [Gong et al., 2025] or tool-grounded verification of table-reasoning steps [Zou et al., 2026]. We adapt signals from these three methods into features computed over the agent’s trajectory, with per-feature sources provided in Appendix I. Closest to us is work on process supervision for intermediate table-reasoning states, where learned or deterministic reward signals score each step of a trajectory and are used to guide, rerank, or halt the reasoning policy, or as a training reward [Zou et al., 2026, Kwok et al., 2026c,a]. In contrast, we never steer or select the agent’s reasoning: we only observe its trajectory, predict whether it will end in a correct delivered answer, and use that prediction to stop or withhold under a reliability objective.

3.2 Decisions 

Our goal is to reduce costly mistakes under RS( λ) while spending as little compute as possible. To accomplish this, we wrap the vanilla agent in a confidence layer (Figure 2) that may intervene on the agent’s own trajectory in two different ways. At every state st (t = 0 , . . . , T ), the layer may EXIT the trajectory and output ⊥ at any given moment t, disregarding the remaining T − t steps. At delivery, if the agent committed to an answer, the layer may WITHHOLD , outputting ⊥ instead of ˆy. Both interventions convert a potential −λ output into one worth at least 0 (exactly 0 if the question in fact was answerable, +1 for correctly abstaining), since the act of abstention is never penalized under

A chance ε that the question is unanswerable raises the exact bar to (λ + ε)/(1 + λ); the gate keeps ε small, and the exact bar changes no reported score by more than 0.01 (Appendix F). Chow’s rule is only optimal for honest probabilities, so the estimate of p is calibrated before thresholding (Section 3.4). The intervention EXIT has no closed form. Stopping a trajectory that Chow’s rule would later withhold leaves the score unchanged and saves the unrun steps, but an intermediate estimate can also stop a trajectory that would have been delivered, so early stoppage can move the score in either direction. Because RS( λ) assigns no value to the steps saved, the EXIT triggers are set empirically (Section 3.4). 

3.3 Estimating confidence from trajectories 

The decisions of Section 3.2 require two conditional probabilities, each available at every intermediate state: the probability that the question is answerable, ˆpans (t) = P (a = 1 | st), and the probability that the trajectory will end in a delivered correct answer, ˆpcorr (t) = P (ˆ y̸ = ⊥, a = 1 , y = 1 | st).Note that answerability is part of the event that ˆpcorr predicts; by chain rule, ˆpcorr (t) factors into 

ˆpans (t) times correctness given answerability, so a trajectory on a likely unanswerable question scores low even when its SQL looks plausible. Either probability can justify an EXIT , since both instances lead to wasted compute. W ITHHOLD uses the terminal estimate ˆpcorr (T ) = P (a = 1 , y = 1 | sT , ˆy),which is exactly the quantity p referenced in Section 3.2. 

Two trajectory-reading heads. We estimate both probabilities with text classifiers (ModernBERT-base [Warner et al., 2024]; Appendix C) that read a plain-text rendering of the state st: the question 

q, followed by each step’s reasoning, query, and result (ri, u i, o i) for i ≤ t. The rendering is left-truncated so that the most recent steps are always retained (2,048 tokens in training, 4,096 at scoring; fewer than 0.1% of transcripts reach either cap). The answerability head estimates ˆpans (t) and is trained with unanswerable ( a = 0 ) as the positive class. Its score at t = 0 is computed from s0 = ( q)

alone, before the agent runs a single step, and serves as a pre-filter. The correctness head is trained on answered answerable questions ( ˆy̸ = ⊥, a = 1 ) and therefore estimates correctness conditional on answerability; Section 3.4 describes how its output is calibrated to the joint quantity ˆpcorr (t) that the decisions require. Neither head consumes hand-engineered features; hand-crafted trajectory features enter only the delivery-time estimator selection of Section 3.4. 

Prefix training. Each collected trajectory is expanded into prefix snapshots at t = 0 , 1, . . . , T , and every snapshot is labeled with the trajectory’s eventual outcome. The final answer line is included only in the terminal snapshot, so each prefix contains exactly what was knowable at that state. All training-pool estimates reported in this paper are out-of-fold: 5-fold cross-validation grouped by question template, so all prefixes of a trajectory, and all questions sharing a template, stay within one fold. 

3.4 Inference procedure 

At inference, the confidence layer applies, in order: 

(1) EXIT gate. EXIT triggers the exact moment ˆpans (t) drops below a gate threshold θ, and the t = 0 reading can refuse a question before the agent runs a single step. θ is predetermined as the largest threshold that wrongly exits at most 0.5% of answerable questions on the calibration pool. The gate is the system’s defense against unanswerable questions. 

(2) Early EXIT (resource-aware mode). Mid run, EXIT also triggers when ˆpcorr (t), calibrated by isotonic regression (a monotone, nonparametric recalibration map; Zadrozny and Elkan, 2002) fit 5on the calibration pool’s prefix snapshots, falls below a stop threshold sλ. Since RS( λ) assigns no value to steps (Section 3.2), sλ is chosen empirically on the calibration pool to maximize RS( λ), ties broken toward more steps saved. 

(3) Chow’s rule at delivery. Once the trajectory reaches the final step T , only committed answers are checked. The correctness estimate is calibrated by a separate isotonic regression fit on every answer delivered in the calibration pool, with answers to unanswerable questions counted as incorrect, so the calibrated value estimates the joint probability p of Section 3.2. Deliver iff the calibrated estimate 

ˆpcorr ≥ τλ = λ/ (1 + λ) (Eq. (2)) and otherwise WITHHOLD . The exact delivery estimator is selected on the calibration pool (Appendix I); we report calibration error before and after. All thresholds, calibration maps, and the estimator selection are frozen on the calibration pool, and held-out pools are evaluated exactly once. 

4 Experiments 

4.1 Setup 

We compare the vanilla agent against the full confidence layer at stakes λ ∈ { 1, 4, 9}, and evaluate its parts separately: the two checks in isolation (gate-only and Chow-only), and the resource-aware mode (early EXIT ), which trades delivered answers for saved compute. 

Benchmark. We use EHRSQL [Lee et al., 2022] on MIMIC-III [Johnson et al., 2016], a benchmark of natural-language questions over a de-identified ICU database that includes questions unanswerable from the schema. From the official train and validation splits we construct three pools with no question template shared between pools: a train pool (6,179 questions; 231 unanswerable), a calibration pool (2,160; 71), and a held-out pool (2,101; 60), evaluated exactly once. The official test split is left untouched. 

Agents. The vanilla agent is a ReAct loop [Yao et al., 2023] in which the model, at each step, produces a thought and optionally SQL, observes the execution result, and finally commits an answer or abstains. Five agent models run under an identical harness and protocol, namely GPT-4o [OpenAI, 2024a] and GPT-4o-mini [OpenAI, 2024b], Qwen2.5-Coder-7B [Hui et al., 2024], Llama-3.1-8B 

[Grattafiori et al., 2024], and Phi-4-mini [Microsoft, 2025]. Full experimental details, including the agent prompt and decoding configuration, are in Appendices H and M. 

Correctness labels. EHRSQL’s official metric is exact execution match, which is strict for an agent that writes its own final query: the executed result can express the gold answer in a different form, such as 90 against a gold 90.0 . We therefore use a semantic label, in which an LLM judge (GPT-4o-mini , itself one of the evaluated agents) deems an answer correct if its executed result is equivalent to the gold query’s executed result; exact matches are auto-correct. The semantic label is primary throughout; labeling details and strict-label scoring are in Appendices B and F. 

Delivery estimator. A pre-registered rule selects, per agent, between the correctness head alone and a gradient-boosted hybrid of the head with ten trajectory features, whichever scores higher on the calibration pool, preferring the simpler within 0.005 . Feature definitions are in Appendix I.

How monitorable an agent is tracks not its capability but how legibly it fails. The two loudest failers, whose trajectories fill with execution errors and fast fabrications, are the easiest to read ( 0.920 , 0.921 ), while GPT-4o , whose rare failures resemble its successes, and Llama-3.1-8B , which meanders through the longest trajectories of the five, are the hardest ( 0.762 , 0.707 ). As agents improve and their failures get quieter, the signal this approach reads may fade. 

Limitations. Our primary correctness label is an LLM judge; a two-rater audit finds it unbiased in aggregate but at odds with the raters on 26% of its hardest cases, and that error propagates to every reported number (Appendix B). The evaluation is limited to a single benchmark and database, and EHRSQL is generous to answerability detection in particular. Its unanswerable questions come from a small set of short templates, and a question-only baseline already reaches 0.955 AUROC, so part of the answerability head’s near-ceiling performance is benchmark structure rather than skill (audit in Appendix A); the design absorbs this, since θ is set by a wrongly-refused tolerance rather than tuned for detection accuracy, but detection will be harder in deployment. This mostly affects the gate, which moves RS( λ) by at most +0 .14 at our 3% unanswerable rate and carries more of the gain at the benchmark’s own 20–33% (Appendix F); correctness given answerability is measured on answerable questions only and draws its signal from the trajectory. We ran no competing confidence method and report one training seed. The confidence heads are also trained per agent on that agent’s own trajectories, so a new agent requires a new collection run, and a monitor frozen at deployment faces an agent whose behavior may drift from the training distribution. 

6 Conclusion and Future Work 

Agentic systems seemingly fail, and in high-stakes settings, the cost of a single delivered mistake can potentially do more damage than one right answer does good. We showed that Sentinel, two small text classifiers reading the agent’s transcript behind utility-derived thresholds, raises the reliability of five text-to-SQL agents at low stakes and, as stakes rise, recognizes on its own when their answers are not reliable enough to deliver. The agent is never modified. Reliability does not have to be built into the agent; our results show that it can be added on top. The confidence signal currently only abstains, and the natural next step is to let it act. At training time, the monitor could serve as a cheap verifier that labels preference pairs or supplies rewards for DPO- or GRPO-style fine-tuning of the agent [Rafailov et al., 2023, Shao et al., 2024], though an agent trained against a fixed monitor may learn to look confident rather than to be correct, and this needs to be tested. At inference time, a budget policy could resample a low-confidence trajectory and rerank the candidates instead of stopping it [Lightman et al., 2024, Zou et al., 2026]. The heads should also be tested on a new database such as eICU, since a monitor that transfers across schemas is far more useful than one that needs to be rebuilt per database. 8Acknowledgments and Disclosure of Funding

I Feature definitions 

The ten trajectory features (Section 4.1) are of three kinds. Token-level telemetry never appears in the transcript, and the schema checks consult a schema file the head never sees, so neither can be recovered from the rendered text. The execution aggregates (empty-result rate, error rate, step count) are visible in the text; they are included as exact counts that the head would otherwise have to infer. Purely linguistic signals such as hedging or self-correction phrasing are excluded: the head already reads those. Every feature is computable from the first t steps alone, with neutral defaults for not-yet-observed quantities; the temporal analyses and gate replays consume exactly this prefix form. 

Uncertainty [Kadavath et al., 2022, Kim et al., 2024, Somov and Tutubalina, 2025]. 

• lp_mean : mean over steps of the per-step mean chosen-token log-probability. • lp_min : minimum chosen-token log-probability across the whole trajectory. • ent_mean : mean over steps of the per-step mean token entropy, computed over the top-5 alternatives at each position (a lower bound on the full entropy). • ent_max : maximum per-token entropy over the trajectory, same truncation; the official EHRSQL baseline thresholds this maximum over the full vocabulary [Lee et al., 2022]. 

Execution [Wang et al., 2018, Gong et al., 2025]. 

• empty_rate : fraction of executed steps whose query returned zero rows. 14 • error_rate : fraction of executed steps whose query raised a SQL error. • n_steps : number of steps taken so far; doubles as the observability index t in the prefix form. 

Schema grounding [Gong et al., 2025]. 

• failed_refs : count, over all logged queries, of table or column references that do not resolve against the database schema, via an alias-aware parser; identifiers that cannot be confidently resolved are conservatively not counted as failures. • bad_joins : count of equality join predicates whose column pair is not backed by a declared foreign-key relationship. • ungrounded_frac : fraction of literal values in the committed SQL traceable to neither the question text nor any previously observed execution result (the database’s shifted time constants are exempt); ungrounded literals are the fabrication signature. 

J Feature analysis: the label-dependent screen 

Each feature is screened for incremental ∆AUROC over BERT-alone (95% CI, template-level cluster bootstrap, 1,000 resamples over fixed out-of-fold predictions). The Phi-4-mini reversal is informative. For the other four agents fabrication is effortful : the agent explores, retrieves something adjacent-looking, and rationalizes it into an answer, so the fabrication carries the cost of the investigation that produced its misleading evidence (Figure 1, Q1). Phi-4-mini 

shows no such signature: both of its outcomes on unanswerable questions are near-instant ( 1.75 vs. 

1.70 steps) while its rare attempts to explore them run to the step cap, consistent with fabrication by reflex — committing from the question’s surface form without gathering evidence — rather than by rationalization. The same shallowness is what makes its transcripts the easiest to monitor (Table 1): a reflex fabrication leaves no competent-looking trail for the correctness head to be fooled by.
