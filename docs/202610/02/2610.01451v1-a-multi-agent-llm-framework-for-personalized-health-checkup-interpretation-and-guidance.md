## 摘要
个性化健康体检结果的解读需要跨纵向记录、医学知识、生活方式指导和医疗导航进行推理。我们提出一个多智能体大语言模型（LLM）系统，该系统识别多种意图，将每种意图映射到特定任务的智能体，并行执行这些智能体，并综合其输出。我们使用合成健康体检记录，在120个结合了两到四项要求的韩语复合查询上，比较了单智能体（Single Agent）和多智能体（Multi Agent）设置下生成的回答。多智能体将加权LLM评判分数从1.695提升至1.797（p = 0.027），另外三个LLM评判员也显示出一致改善（Δ = +0.111至+0.186，所有p < 0.05）。这些提升来自有用性、一致性以及对复合查询中每项要求的处理，而数值准确性和依据性仅在四个评判员中的一个下显著改善，医疗安全性没有差异，关键失败的发生率相近（单智能体15.0% vs. 多智能体13.3%）。两名人类评估者在66.7%和68.3%的成对比较中更偏好多智能体。多智能体执行使延迟和成本分别增加了1.31倍和2.02倍。在探索性亚组分析中，改善集中在涉及个人记录查询的查询上。

## Abstract
Personalized interpretation of health checkup results requires reasoning across longitudinal records, medical knowledge, lifestyle guidance, and healthcare navigation. We present a multi-agent large language model (LLM) system that identifies multiple intents, maps each to a task-specific agent, executes them in parallel, and synthesizes their outputs. We compared answers generated in Single Agent and Multi Agent settings on 120 Korean compound queries combining two to four requirements, using synthetic health checkup records. The Multi Agent improved the weighted LLM-judge score from 1.695 to 1.797 (p = 0.027), and three additional LLM judges showed consistent improvements ($Δ$ = +0.111 to +0.186, all p < 0.05). The gains came from usefulness, consistency, and the handling of every requirement in compound queries, whereas numerical accuracy and grounding improved significantly under only one of the four judges and medical safety did not differ, and critical failures occurred at similar rates (Single Agent 15.0% vs. Multi Agent 13.3%). Two human evaluators preferred Multi Agent in 66.7% and 68.3% of pairwise comparisons. Multi Agent execution increased latency and cost by 1.31$\times$ and 2.02$\times$, respectively. In exploratory subgroup analyses, the improvement was concentrated in queries involving personal-record lookup.

## 1. 核心问题与整体含义

**研究动机与背景**

- **现实缺口**：韩国国家健康筛查项目覆盖人口规模巨大，但体检报告主要以"正常/异常"标签呈现检测值，对纵向变化解读、临床相关性评估以及后续就医行动的支持十分有限。
- **任务复杂性**：健康体检咨询不同于一般医学问答，单一查询往往同时包含多项需求——个人记录检索、医学文献引用、用户自报测量值的判读、生活方式指导、就医服务信息等。例如用户可能同时要求"回顾血压趋势 → 判断是否令人担忧 → 给出生活方式建议"。
- **单智能体瓶颈**：统一 prompt 的单智能体系统难以在长上下文中分离任务专属证据，也难以施加任务专属的安全约束；论文观察到复合查询中常出现"某一项要求得到详细回答、另一项几乎无回应"的失败模式。
- **医疗风险**：无依据的医学断言在健康场景中可能造成伤害，因此显式查询分解比依赖单一无差别推理过程更为必要。

**整体含义**

- 论文提出一个**意图驱动（intent-driven）的多智能体编排框架**：识别复合查询中的多个意图 → 确定性映射到任务专属智能体 → 并行执行 → 综合器合并为连贯回答。
- 与 MedAgents、AutoGen、MetaGPT 等"智能体相互讨论/协作"的系统不同，本框架的智能体**不相互协商**，而是按显式意图分类法与确定性映射执行预设角色，换取可审计性与可控性。
- 主要贡献：(1) 面向异构体检任务的意图式并行编排框架，显式处理复合查询；(2) 带阶段式模型分配与追踪的路由层，使路由决策可审计；(3) 在带标注的韩语基准上覆盖回答质量、关键失败、延迟与成本的评估。

## 2. 方法论

**核心思想**

- 将用户复合查询分解为预定义的任务意图，路由至对应智能体并行执行，再由综合器统一整合，从而在"任务专属证据 + 任务专属安全约束"层面实现可控性。

**问题形式化**

- 第 t 轮输入：用户查询 $u_t$、对话历史 $H_t$、多年体检记录 $D$。
- 意图分类体系 $I$：29 个意图码，归入 7 个承载意图的智能体类别 + 1 个追问建议类别。
- 槽位模式 $S$：13 类槽位，覆盖检验项、疾病名、症状、日期、健康趋势、医院/地区、健康关切、用户自报值等。
- 编排器输出意图集合、关联槽位与候选智能体；每个意图映射到任务专属智能体，输出经综合生成最终回答 $y_t$ 与追问建议。

**系统架构（流程）**

1. **规则前置过滤器**：拒绝含个人标识符或提示注入模式的查询。
2. **并发阶段**：意图分类与 RAG 文档检索并行；随后确定性规则归一化槽位并解析追问。
3. **轻量模型**：从检索到的体检记录与参考文档中选取相关片段。
4. **记忆系统**：提供近期对话轮次、长期事实、会话摘要与语气偏好。
5. **智能体并发执行** → **综合器**整合输出。

**编排器与意图路由**

- 单次调用返回意图、槽位与候选智能体名；校验候选与预定义路由表的一致性，补充映射智能体，剔除未知/重复意图，传播共享槽位，**意图集合上限为 4 个**。
- **仅单智能体意图**（3 个拒答意图 + 医院搜索）优先于其他意图。
- 确定性归一化：相对日期、全历史请求、超出最新体检年份的请求。
- 两个无额外模型调用的规则阶段：
  - **兜底阶段**：在查询线索明确支持时补充遗漏意图、修正判读类型，但不删除已预测意图；
  - **特化阶段**：将泛化医学知识码替换为更具体的码，不改变实际执行的智能体集合。
- 对话规则：省略式追问继承/变换上一轮槽位；自包含复合查询独立于对话历史分类。

**专用子智能体（14 个智能体，13 个由意图映射）**

- **数据分析**：个人结果查询、状态判定查询、整体意见查询、整份报告摘要、跨年比较。
- **医学知识**：生活方式改善、检验-疾病关联、参考范围、发现解释、发现解读、综合分析、贡献因素、检验描述、概念比较、一般筛查知识、后续行动、一般医学问题。
- **判读类（3 个）**：数值判读、分类判读、自由文本判读（针对用户自报值）。
- **营养**：补充剂推荐（基于用户陈述的关切）。
- **医院搜索 / 服务**：地区医疗机构与运营类查询。
- **对话**：默认闲聊智能体 + 单一拒答智能体（覆盖个人数据、越界、注入/系统探测三类；前两类经前置过滤者直接返回固定回复，越界请求由模型生成拒答）。
- **追问建议智能体**：并发生成 3 个追问问题。

**检索与接地**

- 6 个类别维护独立 **FAISS 向量库**，文档由三级医院临床医生审核。
- 词汇重排序对与查询无共享词项的候选降权；共享医学参考检索每轮执行一次，供所有智能体使用。
- 个人记录：轻量模型选取至多 8 个相关检验项码，用于多年记录的精确码过滤。
- 生成前进行**接地检查**；不可用年份或主题明确报告为"不可用"而非推断。

**响应综合（三阶段）**

1. 多智能体输出按固定顺序合并：**个人记录值 → 一般解释 → 建议**；当判读智能体与记录智能体同时运行时，包含判读的一般块置于最前。
2. LLM 精炼：保留每一项已处理要求且保持提问顺序；去冗余；冲突记录值以体检记录为准；**安全规则优先于保留规则**，移除或弱化无依据的医学建议、药物信息、确定性疗效声明、与记录状态不符的陈述。个人记录值单独传入并指示保留引用值、单位、判定与年份；三年及以上序列压缩为最新值 + 趋势句，除非查询明确要求比较或趋势。
3. 规则后处理：去除 LaTeX 与元评论、弱化过于绝对的医学陈述、删除年份归属值与记录不符的句子。

**分层记忆**

- Redis + MongoDB 存近期对话轮次；Qdrant 存嵌入的健康事实与反复关切；用户画像存会话摘要与语气偏好；提取器与决策器异步更新；意图分类器仅接收近期轮次，长期条目在生成阶段使用。

**阶段式模型分配与追踪**

- 轻量模型：分类、抽取、追问建议、精炼；推理模型：数据分析、医学知识；其他模型：判读、营养、服务、医院搜索。
- HyperCLOVA X 调用受限流时用备选模型重试；集中式追踪层记录 provider、模型、调用智能体、token 数与延迟，非模型操作以工具事件在同一 turn-level trace ID 下记录。

## 3. 实验设计

**数据集 / 场景**

- **韩语基准**：120 条复合查询，覆盖 7 个承载意图类别中的 4 个——数据分析（记录查询、结果解读、跨年比较、整报摘要）、医学知识、判读（数值/分类/自由文本）、营养（补充剂推荐）。
- **未纳入**：医院搜索、服务、对话类别（医院搜索与三类拒答意图被配置为单独运行；无查询指向其余服务或闲聊意图）。
- **合成体检记录**：5 份，每份含 2020–2025 年最多 6 次年度检查，包含异常发现与整体意见评论；检验值按经临床审核的院内标准落入预定义判定类别（正常、注意、异常、其他）。
- 评估项标注目标意图，并在适用时标注由预定义记录推导的真值。

**对比方法**

- **Single Agent**：单意图识别 → 执行对应智能体 → 经同一综合器（含 LLM 精炼、安全规则、规则后处理），仅省略多智能体合并阶段。
- **Multi Agent**：多意图检测 + 智能体路由 + 并行执行 + 综合器合并。
- 两配置在 prompt、RAG、综合器精炼/安全规则/后处理上完全一致，唯一差异是意图数量、执行智能体数与是否合并多智能体输出。

**评估指标**

- **路由**：微平均精确率/召回率/F1、执行智能体集合的精确集合匹配。
- **效率**：总延迟、首 token 时间、输入/输出 token、模型调用数、成本。
- **回答质量**：盲评 LLM 评判员（0–2 加权评分表 + 关键失败门控），4 名评判员：Claude-Opus-5.5、GPT-6-Sol、**Gemini-3.8-Flash（主评判员，独立提供方）**、Solar-Pro-4（独立提供方）。
- **人工评估**：2 名非作者、非临床的 QA 专员，盲法随机呈现的强制选择成对比较。
