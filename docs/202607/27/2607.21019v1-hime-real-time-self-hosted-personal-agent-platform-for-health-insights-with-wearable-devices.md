## 摘要
传统上，对智能手表等可穿戴健康信号的分析受限于僵化的分析框架和有限的个性化。LLM智能体的出现为个人健康智能体分析创造了新机遇，在这种分析中，健康洞察可以自适应地、在上下文中生成。然而，目前尚无能够实时处理个人健康数据同时保护隐私的开源本地可部署平台。我们提出了HiMe，一个本地可部署、隐私优先的智能体平台，与广泛的可穿戴设备的实时健康数据生态系统完全兼容。HiMe遵循三项设计原则：数据库被视为一等组件；有效性和效率共同优化以实现低成本的帕累托最优平衡；数据在实时处理的同时对用户进行长期建模。这些原则共同使得个人能够利用个人健康智能体进行持续、个性化的健康监测，以实现更好的健康状态。

## Abstract
Traditional approaches to wearable health signal analysis, such as smartwatches, are constrained by rigid analytical frameworks and limited personalisation. The emergence of LLM agents creates a new opportunity for Personal Health Agentic Analysis, where health insights can be generated adaptively and in context. However, currently there is no open-source locally deployable platform capable of processing personal health data in real time while preserving privacy. We present HiMe, a locally deployable, privacy-first agent platform that is fully compatible with real-time health data ecosystems across a wide range of wearable devices. HiMe is guided by three design principles. The database is treated as a first-class component. Effectiveness and efficiency are jointly optimised to achieve a low-cost Pareto-optimal balance. Data are processed in real time while the user is modelled over the long term. Together, these principles make it practical for individuals to harness Personal Health Agents for continuous, personalised health monitoring for better wellbeing.

- **核心思想**：将数据库视为一等组件；联合优化效果与效率以寻求低成本的帕累托最优；结合实时数据处理与长期用户建模。
- **系统架构**（四层）：

  - **智能体层**：交互智能体作为主智能体，可调用分析子智能体、管理子智能体（负责记忆更新和主动任务）、计划子智能体（负责个性化健康计划）。提示词采用模块化分层（系统指令、角色、职责等），支持 KV 缓存复用。
  - **交互层**：用户通过内置聊天或第三方消息平台（微信、Telegram）访问；智能体可自编时间/事件触发任务，推送通知到手机和手表；包含一个像素猫数字孪生反映实时健康状况。
- **关键设计原则具体体现**：
  - 数据库作为一等组件：智能体是持久状态上的接口，而非临时推理引擎；用户模型为 Markdown 格式（非向量存储），便于检查终端状态和自动化评估。
  - 联合优化效率：轻量级过滤（如统计触发器）先行，仅在触发时才调用昂贵的 LLM 分析；窄角色携带小提示词，路由到最便宜合适的模型；静态前缀提高 KV 缓存复用。
  - 实时+长期：低成本组件全分辨率监控流，LLM 仅在有意义触发时唤醒；捕捉瞬时异常和长期趋势。

### 3. 实验设计：数据集、基准、对比方法

- **数据集**：五个公开可穿戴语料库——LifeSnaps、PMData、MMASH、CovIdentify、GLOBEM。每个数据集通过数据适配器回放，模拟实时数据流。
- **基准**：HiMe 本身是演示系统，但根据第一原则（数据库终端状态可检查）设计了自动化评估体系。对于能力评估，采用 pass@1（3次运行）和终端状态 oracle（无需 LLM 裁判）。
- **对比方法/模型**：22 个 backbone，19 个本地模型（Qwen2.5、Qwen3、Qwen3.5、Qwen3.6、Gemma-4 等，参数量 1.5B～35B；以及 nemotron-3-nano、granite-4.1-8b、glm-4.7-flash）；3 个托管 API 模型（GPT-5-mini、DeepSeek-V4-flash、Gemini-3.5-flash）作为前沿参考。
- **评估任务**：
  - 按角色能力（Route、Analysis、Memory、Plan、Hallucination）
  - 复合遍历（Composite Rundown）：5 轮持久聊天会话
  - 数据到报告（Data-to-Report）：跨模态（时间序列到自然语言摘要）评估，使用固定 LLM 裁判对照参与者自我报告评分

  - 纵向真实用户研究（Longitudinal Real-User Study）：9 名非技术参与者使用两个月，五分 Likert 量表反馈

### 6. 论文的主要结论与发现

- **本地模型可匹敌 API 模型**：最强本地 backbone（Qwen3.6-27b、Qwen3.5-35b-a3b）在分析任务上达到 0.91 pass@1，综合超过 DeepSeek-V4-flash（0.85）和 GPT-5-mini（0.76），仅 Gemini-3.5-flash（0.94）明显领先。且本地模型无幻觉。
- **能力不随参数规模单调增长**：MoE 模型（30B 总参，3B 激活）在分析上不如更小的稠密 8B 模型。
- **小模型不足**：1.5B 模型在所有能力上失败，幻觉率高达 0.47。
- **多轮可靠性是瓶颈**：复合遍历中每轮分数高（Gemini 0.98，Qwen3.5-35b 0.96），但全部 5 轮都成功的比率很低（最高 Gemma-4-26b 0.44），误差累积严重。
- **数据到报告任务仍困难**：即使是分析得分 0.94 的 Gemini-3.5-flash，在生成个性化报告（疲劳、压力等）上也仅 14.6%，说明主观状态叙述与数值检索是不同能力。
- **触发机制有效降低成本**：智能体自编的统计触发器比固定轮询检测更多异常，且大幅减少 token 使用（小模型 121 倍节省，中大模型 ~50 倍）。
- **用户研究正面但维度不均**：可用性（4.67/5）和主动性（4.56/5）评分最高，个性化计划适配（4.00/5）最低，部分用户认为计划变化适应慢。

### 7. 优点

- **隐私优先、本地部署**：所有数据保留在用户硬件，完全开源。
- **模块化分层架构**：四层设计（数据、工具、智能体、交互）职责清晰，易于扩展和调试。
- **可测量性**：利用数据库终端状态提供自动化评估，无需 LLM 裁判（除了数据到报告任务）。
- **事实验证**：工具输出经过验证器检查，增强可审计性和可信度。
- **实时触发机制**：廉价统计条件连续运行，仅在触发时唤醒 LLM，在保持高回忆率的同时大幅降低延迟和成本（小模型最高节省 121 倍 tokens）。
- **对研究人员友好**：可作为可穿戴智能体基准测试平台。
- **支持多种设备和消息渠道**：兼容主流可穿戴设备和 WeChat、Telegram 等。
- **提供了全 22 个 backbone 的详细结果和消融实验**，实验透明。

### 8. 不足与局限

- **多轮可靠性低**：即使高性能模型也难以在 5 轮对话中保持零失败，s5 得分最高仅 0.44，会话级可靠性仍是未解决的前沿问题。
- **数据到报告能力弱**：LLM 无法可靠地将时间序列转换为与用户自我报告一致的自然语言摘要，可能限制实际应用价值。

- **用户研究规模小、无对照**：9 名自选参与者，偏差风险高；缺乏长期效果验证（如健康指标改善）。
- **触发机制潜在风险**：作者承认无法保证触发器完全可靠，可能漏报或误报。
